## 3. Must fix before publishing (ranked)

**A. Burchett works 12/30, 12/31, 1/1 as primary and 1/2–1/3 as backup — five straight days.** His stated hard rule is
"more than 2 consecutive 24-hour periods is no longer an option". The cause is a global default,
`groupRules.holidays.unitExemptFromMaxConsecutive = true`, invented so Khan's 4-day Thanksgiving unit could pass his own
max of 3, and `countBackupInConsecutive = false`, which makes backup runs unlimited. The preview's "Max consec. 2"
column for Burchett hides the run because it collapses the same way and splits at the month boundary. Across 30 seeds of
the milestone range, 12 give Burchett three straight primaries and 27 give him more than two consecutive on-call days.

**B. Thanksgiving Thu–Sun (11/26–29) is locked to Khan and recorded as "CONFIRMED (Faraz 9/21 evening)".** Every record
I have from the daytime says *pending* ("[removed]"); the confirmation and
the 4-day unit were both written by Claude Code in commit `f03b9b1`, attributed to an evening chat. If that chat happened,
fine — but it is a lock in the live database with knock-on effects: Fierce is the only eligible Thanksgiving backup and
lands exactly on his 14-day November cap, and Khan is on call six straight days (11/25 B, 11/26–29 P, 11/30 B). Confirm
it explicitly, and if it stands, express Khan's 4-day allowance as *his* `maxConsecutiveDays`, not a global exemption.

**C. Fierce's Silvis-primary week 12/7–12/13 is not from published Davenport data.** Davenport is published through the
week of 11/9. The 12/7 week comes from `s5.eastFeed.statedWeeks` (a stated expectation) and a 100-run forecast (the seed
says 200; the script ignores it). Three related defects: a forecast day is consulted even inside published coverage,
so a stale forecast can block you after Davenport publishes; `east_overrides busy:false` cannot clear a forecast-busy
day; and Setup says "published weeks replace the forecast automatically", which is not true — there is no code path
that prunes `east_forecast`. Sequence matters: generate the next Davenport period first, refresh the East feed, then
regenerate Silvis December.

**D. Server-side trade hole.** `shift_trade_requests` has an INSERT policy that checks only `from_surgeon_id` and no
insert trigger, while `trade_update_guard` runs only on UPDATE. A signed-in surgeon can insert a row with
`status='accepted'` naming any counterparty, then call `apply_trade()` and swap shifts without consent. `apply_trade()`
also applies no eligibility, vacation or lock check (a locked import day transfers with its lock flag intact; a trade can
put someone on their own vacation). Low likelihood among six colleagues, high impact, easy fix — do it before inviting
anyone.

**E. Philip's "prefers not a full week" is not implemented** (`preferences.noFullWeek` is read nowhere). With backup not
counted in runs he holds 12/22 P, 12/24–25 B, 12/26–29 P — six consecutive on-call days. Khan has the same shape
around Thanksgiving. Implement an any-role consecutive limit (soft or hard, per surgeon).

**F. Personal wording in the anon-readable blob.** "[removed]" (Acton's Thanksgiving note) and "[removed]"
(his Tuesday note) are readable with the public key. The importer scrubs only vacation notes. Strip or reword every
`note`/`*Note` field before it reaches `call_schedule_data`.

**G. The regression harness cannot see the year boundary.** It runs Nov–Dec and Jan–Mar as separate ranges, never
2026-11-02 → 2027-01-03, and checks consecutive runs only for Burchett and Sarkar — which is why CI is green while
finding A exists. Add the milestone range and any-role run checks for all six.

**H. Day-before rules were narrowed to primary only.** The vacation trailing edge and Philip's day-before-Aledo apply to
primary; backups are allowed (Acton is backup on 11/18 and 11/24, the days before his vacations). The rules doc had no
role qualifier. Decide; if backups must stay off, flip `dayBeforeRules.trailingEdgeRoles` / `aledoDayBeforeRoles` to
both roles and widen the DB trigger.

Smaller items in the same fix prompt: Fierce cannot *receive* a weekend block by trade (the trade path never passes
`asBlockMember`); the day editor fails open if eligibility throws; Burchett's explicit December list can be waived on
12/24 (soft only) although he deliberately left 12/24 off it; the seed's `forecast.runs: 200` is not what ran; the
"handoff partner" diagnostics check promised for Sarkar does not exist.
